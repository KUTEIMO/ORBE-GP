## 1. Mapa de arquitectura

Orbe360 es un SaaS de tours 360° multi-empresa construido sobre **un solo motor
compartido**. No hay copia del visor por cliente: el contexto (`org`, `tour`) sale de
la URL y todo lo demás se resuelve por datos.

```
Navegador
  │
  ├─ /                                  → plataforma/index.html   (landing Orbe)
  ├─ /plataforma/login.html             → login global
  ├─ /plataforma/superadmin.html        → superadmin (crea orgs/tours/usuarios)
  ├─ /{org}/org-admin.html              → plataforma/org-admin.html
  ├─ /{org}/{tour}/                     → index.html              (visor Marzipano)
  ├─ /{org}/{tour}/control-web/         → control-web/index.html  (editor del tour)
  └─ /{org}/{tour}/panoramas|assets/…   → media/{org}/{tour}/…
  │
  ▼
scripts/dev-server.mjs   ── rewrites virtuales + guardas de seguridad
  │                         (en producción lo reemplaza Caddy/Nginx con las mismas reglas)
  │  · DEMO_PUBLIC=1 → bloquea secretos, org-admin y superadmin
  │  · proxy mismo origen /__convex/api/{query|mutation|action} → :3210
  ▼
Convex (:3210)  ── 12 módulos de funciones, 12 tablas, authz por sesión
```

### Capas

| Capa | Ubicación | Responsabilidad |
|------|-----------|-----------------|
| **Motor visor** | `src/` (21 módulos ES, ~150 KB) | Marzipano, hotspots, accesibilidad, navegación espacial, branding |
| **Editor** | `control-web/` (`admin.js` 104 KB) | Grafo de escenas, hotspots, media, publicación |
| **Plataforma** | `plataforma/` | Landing, login, org-admin, superadmin, tokens de diseño |
| **Backend** | `convex/` | Schema, auth, RBAC, grafo, media, branding, accesibilidad |
| **Routing** | `scripts/dev-server.mjs` + `orbe-config.js` | URL virtual multi-tenant (servidor y cliente) |
| **Assets** | `media/{org}/{tour}/` | Panoramas y accesibilidad aislados por tenant |
| **Tooling** | `scripts/` (19 archivos) | Seeds, migraciones, QA, auditorías, TTS |

### Resolución del contexto de tour

Se resuelve **dos veces** de forma coherente, que es lo que permite servir un solo HTML:

1. **Servidor** (`resolveRoute` + `mapTourRest`): `/{org}/{tour}/rest` → archivo real.
   Los panoramas y `config.json` se sirven **solo** desde `media/{org}/{tour}/`; el
   `/panoramas/` compartido de la raíz devuelve `410 Gone` a propósito. Si falta el
   `config.json` de un tenant se devuelve un stub vacío aislado en lugar del campus de otro.
2. **Cliente** (`orbe-config.js`): `location.pathname` → `__ORBE_ORG_SLUG__` /
   `__ORBE_TOUR_SLUG__`, con `?slug=` como compatibilidad y alias
   (`unisimon-campus` → `experienciavirtual`).

Coincide con el contrato canónico de
[producto/32-routing-multi-empresa-url.md](../producto/32-routing-multi-empresa-url.md).
Las fases P0 y P1 del doc 32 están **implementadas**, incluido el índice compuesto
`tours.by_org_and_slug` que allí figuraba como pendiente.

### Modelo de datos Convex (12 tablas)

| Tabla | Índices | Notas |
|-------|---------|-------|
| `organizations` | `by_slug` | `maxTours` = cuota blanda |
| `platformUsers` | `by_email` | PBKDF2 100k iteraciones, comparación en tiempo constante |
| `memberships` | `by_user`, `by_org`, `by_user_and_org` | roles `orgAdmin` / `tourEditor` / `tourGuest` |
| `guestTourDrafts` | `by_user_and_tour` | Overlay personal del invitado; nunca escribe filas de producción |
| `sessions` | `by_token`, `by_user` | Token de 32 bytes, expiración explícita |
| `loginAttempts` | `by_email` | Anti fuerza bruta |
| `tours` | `by_slug`, `by_org`, `by_org_and_slug`, `by_published` | `published` es la puerta de lo público |
| `scenes` | `by_tour`, `by_tour_and_file` | `initialView` separa "vista de entrada" de las coordenadas de hotspot |
| `hotspots` | `by_scene`, `by_tour`, `by_client_key` | `yaw`/`pitch` en coordenadas de imagen |
| `connections` | `by_tour`, `by_from` | Grafo de navegación |
| `assets` | `by_tour`, `by_org`, `by_object_key` | `objectKey` = `orgs/{orgId}/tours/{tourId}/…`, listo para R2/S3 |
| `tourBrandings` | `by_tour`, `by_org` | White-label por tour, separado del chrome de Orbe |

**Lo que cumple buenas prácticas:**

- Documentos planos y relacionales, sin anidamiento profundo. Correcto.
- **Cero `.filter()` de base de datos.** Las 18 apariciones de `.filter(` son filtros de
  array de JavaScript sobre resultados ya acotados por índice. Correcto y poco común.
- **40 de 40** funciones públicas declaran `args` y `returns`. Correcto.
- `Date.now()` evitado en rutas de query: `getUserBySession` acepta un `now` del cliente
  precisamente para no romper el cacheado reactivo. Detalle bien pensado.
- Authz centralizada en `convex/lib/authHelpers.ts`; `userCanEditTour` devuelve `false`
  para superadmin, como exige el contrato de producto.

**Lo que no:**

- **Cero paginación.** 57 `.collect()`, ninguno `.paginate()`. Nueve de ellos escanean
  tablas enteras (`organizations`, `tours`, `platformUsers`) sin índice. Ver riesgo R3.
- **Cuatro índices redundantes** detectados por `@convex-dev/no-duplicate-indexes`:
  `memberships.by_user` ⊂ `by_user_and_org`, `tours.by_org` ⊂ `by_org_and_slug`,
  `scenes.by_tour` ⊂ `by_tour_and_file`, `hotspots.by_tour` ⊂ `by_client_key`.
  Cada índice de más encarece toda escritura.
- **~77 llamadas `ctx.db.get(id)` sin nombre de tabla**, la forma antigua de la API.
- La autenticación pasa el token como **argumento en cada función pública** en lugar de
  usar wrappers `customQuery` / `customMutation` de `convex-helpers`. Funciona, pero
  repite el mismo bloque de authz decenas de veces: es justo el patrón que la guía de
  Convex recomienda encapsular.

### Pipeline de assets y rendimiento

| Dato | Valor |
|------|-------|
| Panoramas Unisimón | 62 JPEG equirectangulares, 243,4 MB, ~3,9 MB de media, 4,2 MB el mayor |
| Sandbox Orbe | 4 JPEG, 16 MB |
| Formatos alternativos | ninguno (sin WebP/AVIF, sin miniaturas, sin tiles) |
| Caché HTTP | `max-age=86400, stale-while-revalidate=604800` para imágenes y audio |
| Precarga | `<link rel=preload>` de la escena de entrada (solo en el árbol de la demo) |

El motor descarga la **equirectangular completa por escena**. Cada salto entre escenas
son ~4 MB. En la red del campus no se nota; en móvil con datos, sí.

## 2. Divergencia ORBE ↔ PROTOTIPO

Este es el problema más grave del repositorio y conviene entenderlo bien, porque la
intuición es al revés de la realidad.

### Qué encontré

| | ORBE (`APLICATIVOS\proyectos unisimon\ORBE`) | PROTOTIPO (`gestion de proyectos\PROTOTIPO-360-CURSOR-V1`) |
|--|--|--|
| Rol declarado | Repo "producto" | Copia del curso |
| Rol real | **Código congelado el 2026-09-16** | **Código vivo: sirve la demo pública** |
| Historia git | Idéntica (`51123ae`), mismo remoto | Idéntica |
| `media/` | 410 archivos | 410 archivos, **byte a byte iguales** |

**El puerto 8081 lo sirve PROTOTIPO**, no ORBE. Lo confirmé pidiendo `/LEEME.md`
(existe solo en ORBE): devuelve **404**.

### Inventario de la divergencia (31 archivos)

Medido con `npm run check:drift`, que normaliza CRLF/LF:

**Solo en ORBE (6):** `LEEME.md`, `css/design-tokens.css`, `eslint.config.mjs`,
`scripts/audit-responsive-a11y.mjs`, `scripts/check-tree-drift.mjs`, `scripts/probe-overflow.mjs`

**Solo en PROTOTIPO (1):** `scripts/start-demo.mjs` — el entrypoint de la demo pública

**Contenido distinto (24).** La dirección no es uniforme, y ese es el peligro:

| Gana PROTOTIPO (13 de hoy) | Gana ORBE (7) |
|---|---|
| `convex/schema.ts`, `auth.ts`, `organizations.ts`, `tourAdmin.ts`, `seed.ts`, `branding.ts`, `lib/authHelpers.ts` | `README.md`, `UBICACION_Y_ARCHIVO.md` |
| `control-web/admin.js`, `auth-gate.js` | `docs/producto/57-*`, `58-*` |
| `src/viewer.js`, `configLoader.js`, `hotspotManager.js` | `css/base.css`, `plataforma/tokens.css`, `control-web/admin.css` |
| `scripts/dev-server.mjs`, `plataforma/index.html`, `login.html`, `index.html` | |

Es decir: **el backend y el motor viven en PROTOTIPO; la documentación y el trabajo
reciente de CSS viven en ORBE.** No existe un árbol que sea superset del otro. Cualquier
"copiar una carpeta sobre la otra" pierde trabajo.

### Cuánto crece

La divergencia está creciendo **ahora mismo**, no es un residuo histórico. Medida tres
veces durante la propia auditoría (unos 40 minutos):

| Momento | Archivos divergentes |
|---------|---------------------|
| Inicio de la auditoría | 31 |
| A mitad | 37 |
| Al cerrar | **45** |

De los 14 nuevos, 6 son de esta auditoría (documentos, `eslint.config.mjs`,
`check-tree-drift.mjs`); los otros 8 (`control-web/admin-pro.css`,
`css/design-tokens.css`, `scripts/audit-contrast.mjs`, `scripts/probe-*.mjs`…) los creó
otro trabajo en paralelo sobre ORBE mientras la demo seguía sirviéndose desde PROTOTIPO.
Esa es exactamente la dinámica que hay que cortar.

## 3. Riesgos por severidad

### R1 — Dos árboles divergentes sin fuente de verdad · **CRÍTICO**

Ningún árbol es superset. El schema de Convex, la autorización y el motor del visor
difieren entre el código que se edita y el código que se demuestra. Se puede arreglar un
bug en ORBE, verificarlo, y que la demo pública siga rota; o cambiar el schema en
PROTOTIPO y que ORBE deje de compilar contra el mismo despliegue de Convex (los dos
apuntan al **mismo** `.env.local`, así que comparten base de datos).

> **Recomendación:** ejecutar el plan de unificación de la sección 4 **antes** de
> cualquier otro cambio de arquitectura. Es la deuda que bloquea a todas las demás.

### R2 — `media/` (272 MB) no está versionado ni respaldado fuera de los dos árboles · **CRÍTICO**

`media/` nunca ha estado en git (0 archivos trackeados). Las dos únicas copias están en
la misma máquina, en el mismo disco. Los 62 panoramas de Unisimón son irrepetibles sin
volver a hacer la captura con la cámara.

> **Recomendación:** hoy mismo, copia a almacenamiento externo (disco o nube). Después,
> mover los binarios a object storage (`assets.objectKey` ya está diseñado para R2/S3) y
> dejar en el repo solo referencias. El `media-manifest.csv` del respaldo sirve para
> verificar integridad, pero un manifiesto no restaura nada.

### R3 — Sin paginación en ninguna query · **ALTO**

57 `.collect()`, cero `.paginate()`. Los escaneos de tabla completa sobre
`organizations`, `tours` y `platformUsers` son correctos con 1 organización y 62 escenas,
y dejan de serlo con 50 clientes. `listTours` y el dashboard del superadmin son los
primeros que se degradan.

> **Recomendación:** paginar antes de dar de alta al segundo cliente real. Empezar por
> `organizations.ts:149-151` (tres tablas completas en una sola query) y `auth.ts:299`.

### R4 — Contraseña de la demo en claro en el repositorio · **ALTO**

`scripts/start-demo.mjs` contiene `invitado@unisimon.local` / la contraseña literal, y el
archivo está versionado y se sube al remoto de GitHub. El túnel es público.

> **Recomendación:** mover a variable de entorno o a `.env.local`, e imprimirla en consola
> desde ahí. Rotar la contraseña actual. El archivo ya está en la lista de bloqueo HTTP del
> servidor, así que no se filtra por el túnel, pero sí por el repositorio.

### R5 — Sin ESLint, sin `typecheck`, sin CI · **ALTO** *(parcialmente resuelto)*

No existía ninguna verificación estática. La primera pasada de ESLint encontró
22 errores y 106 avisos reales, incluidos los cuatro índices redundantes. Resuelto en
ORBE (sección 5); pendiente propagarlo al árbol unificado y a CI.

### R6 — Autorización repetida en cada función en vez de wrappers · **MEDIO**

Cada función pública recibe `token` y repite `requireUser` → `getMembership` →
comprobación de rol. Basta olvidarlo una vez para abrir una fuga. Ya hay un script
dedicado (`verify-control-web-authz.mjs`) que existe precisamente porque el patrón es
frágil.

> **Recomendación:** `convex-helpers` con `customQuery` / `customMutation`:
> `authedQuery`, `orgQuery`, `tourEditorMutation`. Migración incremental, función a función.

### R7 — Monolitos de front · **MEDIO**

`control-web/admin.js` = 104 KB en un archivo; `src/configLoader.js` = 39 KB;
`convex/tourAdmin.ts` = 28 KB. Sin bundler ni tests unitarios, cualquier cambio en
`admin.js` se verifica a ojo.

> **Recomendación:** partir `admin.js` por dominio (grafo / escenas / hotspots / media /
> publicación) aprovechando que ya son módulos ES nativos. No requiere build.

### R8 — Panoramas de 4 MB sin derivados · **MEDIO**

Sin WebP/AVIF, sin miniaturas, sin tiles. ~4 MB por salto de escena.

> **Recomendación:** generar WebP (ahorro típico 30-50 % sin pérdida visible) y una
> miniatura de baja resolución para mostrar mientras carga la completa. Marzipano soporta
> tiles multirresolución si más adelante hace falta.

### R9 — Datos de tenant incrustados en el backend · **MEDIO**

`convex/lib/campusSpatialPackage.ts` (133 KB) y `pilotA11yPackage.ts` (40 KB) son datos
de Unisimón compilados dentro del código del backend. Cada cliente nuevo así multiplica
el tamaño del despliegue y obliga a desplegar código para cambiar contenido.

> **Recomendación:** mover a `media/{org}/{tour}/` o a tablas de Convex, e importarlos.

### R10 — Cuatro índices redundantes · **BAJO**

Encarecen cada escritura sin dar capacidad de consulta nueva. Detectados
automáticamente; el arreglo es mecánico (borrar el índice corto y cambiar la llamada al
compuesto), pero toca rutas de consulta activas, así que va después de la unificación.

## 4. Plan de unificación ORBE ↔ PROTOTIPO

### Principio

**ORBE es la fuente de verdad** (es el repo "producto", tiene el remoto y la
documentación más reciente). **PROTOTIPO pasa a ser un despliegue**, no un lugar donde se
edita.

No al revés: mover el producto a la carpeta del curso consolidaría la confusión que
[producto/58-curso-vs-orbe-aplicativos.md](../producto/58-curso-vs-orbe-aplicativos.md)
intenta deshacer.

### Fase 0 — Congelar (hecho)

Los dos árboles tienen tag y respaldo: ver
[VERSION-ESTABLE-2026-09-29.md](../VERSION-ESTABLE-2026-09-29.md).

### Fase 1 — Reconciliar en una rama, sin tocar la demo

```bash
cd "C:\Users\SOTO\APLICATIVOS\proyectos unisimon\ORBE"
git switch -c unificacion-2026-09-29
npm run check:drift          # lista exacta y actualizada de archivos
```

Traer de PROTOTIPO **solo** los 17 archivos donde gana (backend, motor, routing,
`start-demo.mjs`) y **revisar el diff de cada uno** antes de aceptarlo. Los 7 donde gana
ORBE se quedan. `package-lock.json` se regenera, no se copia.

```bash
git diff --no-index "$PROTO/convex/schema.ts" convex/schema.ts   # revisar
copy "$PROTO\convex\schema.ts" convex\schema.ts                  # aceptar
```

Criterio para aceptar un archivo de PROTOTIPO: que el diff sea **puramente aditivo**
respecto a ORBE. Los que encontré (ejemplo: `index.html` añade `preload` y cache-bust) lo
son. Si alguno no lo es, se resuelve a mano.

### Fase 2 — Verificar en un puerto distinto

**El túnel no se toca.** La verificación corre en paralelo:

```bash
$env:PORT=8082; npm start        # ORBE unificado en :8082
npm run typecheck
npm run lint
npm run check                    # qa + authz + rutas + a11y
npx playwright test
```

Comparar `:8082` con `:8081` escena por escena. **Los hotspots no se tocan en ningún
momento**: el grafo vive en Convex y los dos árboles apuntan al mismo despliegue, así que
la comparación es del motor, no de los datos.

### Fase 3 — Cambiar la demo de árbol

Solo cuando la fase 2 esté verde. **`cloudflared` sigue corriendo**: apunta a
`127.0.0.1:8081`, y le da igual qué proceso escuche ahí.

```bash
# 1. Parar solo el servidor estático (PID 54276), no cloudflared
Stop-Process -Id 54276

# 2. Arrancar el mismo puerto desde ORBE
cd "C:\Users\SOTO\APLICATIVOS\proyectos unisimon\ORBE"; npm run start:demo

# 3. Verificar de inmediato
curl.exe -s -o NUL -w "%{http_code}" https://dog-them-forgot-criticism.trycloudflare.com/
```

Ventana de corte: unos segundos. Si algo falla, se vuelve a arrancar PROTOTIPO en :8081 y
la URL sigue viva. Mejor hacerlo cuando nadie esté usando la demo.

### Fase 4 — Cerrar el árbol viejo

1. `PROTOTIPO-360-CURSOR-V1/LEEME-ARCHIVADO.md`: "árbol archivado el 2026-09-29, el
   producto vive en `APLICATIVOS\proyectos unisimon\ORBE`, no editar aquí".
2. Confirmar que la única copia de `media/` de referencia es la de ORBE (y que hay una
   externa — riesgo R2).
3. `npm run check:drift` debe salir en verde.

## 5. Estado de la verificación estática (nuevo)

`npm run lint` y `npm run typecheck` ya funcionan en ORBE.

| Comprobación | Resultado |
|--------------|-----------|
| `npm run typecheck` (`tsc` sobre `convex/`) | ✅ 0 errores |
| `npm run lint` | ⚠️ 22 errores, 106 avisos |

Los 22 errores, por regla:

| Regla | Nº | Qué es |
|-------|----|--------|
| `@typescript-eslint/no-unnecessary-type-assertion` | 10 | `as` que no cambian nada |
| `@convex-dev/no-duplicate-indexes` | 4 | Riesgo R10 |
| `@typescript-eslint/require-await` | 3 | `handler` async sin `await` |
| `prefer-const` / `no-useless-assignment` / `no-useless-escape` | 5 | Limpieza menor |

Los 106 avisos son casi todos `@convex-dev/explicit-table-ids` (la migración de
`ctx.db.get(id)` a `ctx.db.get("tabla", id)`), degradado a aviso a propósito para que el
lint sea utilizable desde el primer día.

**No corregí ninguno.** Todos están en archivos que también existen en PROTOTIPO:
arreglarlos ahora añadiría 20 archivos más a la divergencia justo cuando el problema
número uno es la divergencia. Corresponde hacerlo en la fase 1 de la unificación, de una
sola pasada.
